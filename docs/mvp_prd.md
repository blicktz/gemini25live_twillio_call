**Core Requirements:**

     * Handle the continuous bi-directional audio flow. Audio generated by the Gemini API (e.g., 24kHz LPCM16) **must** be resampled to 8kHz LPCM16, then encoded to MuLaw, and sent back to Twilio over the WebSocket as outbound media messages (JSON containing base64 encoded audio payload).    * **Full-Duplex Communication:** Ensure that audio can be sent to Gemini while simultaneously receiving audio responses, enabling natural interruptions (barge-in). The application should handle stopping playback of AI-generated audio if the caller starts speaking.

4. **Audio Processing (Low Latency Focus):**  
   * Implement efficient and low-latency audio transcoding (MuLaw \<-\> LPCM16) and resampling (8kHz \<-\> 16kHz, 24kHz \-\> 8kHz).

   * Implement appropriate audio buffering strategies to manage network jitter and ensure smooth audio flow for both inbound and outbound audio.  
5. **Error Handling and Robustness:**  
   * Implement comprehensive try-except blocks for API calls, WebSocket operations, and audio processing.  
   * Log important events (call start/end, WebSocket connection/disconnection, API errors) and errors to the console for debugging.  
   * Handle WebSocket disconnections gracefully and terminate the Gemini API session if the Twilio stream ends.  
6. **MVP Scope:**  
   * Focus on the core functionality: connecting a caller to a Gemini-powered AI for a real-time, full-duplex voice conversation.  
   * No advanced features like call recording storage, complex CRM integrations, or database persistence are required.
